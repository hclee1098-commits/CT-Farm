## 처음 설치

Windows PowerShell 5.1, Node.js 22 이상, 실행 중인 Docker Desktop이 필요합니다. ZIP을 **새 프로젝트 폴더**에 풀고 그 폴더에서 PowerShell을 여세요. CT-Farm 폴더에 덮어쓰지 마세요.

```powershell
.\SECURE-LIFECYCLE.ps1 -Action SETUP
.\SECURE-LIFECYCLE.ps1 -Action STARTER
```

SETUP은 환경파일과 프로젝트 식별자 생성, 포트 선택, DB 준비와 빌드를 수행합니다. Git에서 받은 소스에 실제 `.env`가 없는 것은 정상입니다. **SETUP이 생성하며 예시 파일을 운영 비밀키로 사용하지 않습니다.** 이미 있는 환경파일을 지우거나 새 예시로 덮어쓰지 마세요. 오류가 나면 아래 문제해결 문서를 확인합니다.

STARTER가 출력하는 웹 주소를 브라우저로 여세요. 기본 웹 3000/API 4000이지만 사용 중인 포트에 따라 달라질 수 있습니다. 화면에서 회원가입 → 로그인 → 게시글 등록 → 파일 업로드 순으로 확인하세요. 관리자 화면은 일반 계정으로 접근할 수 없습니다.

## 종료와 재실행

```powershell
.\SECURE-LIFECYCLE.ps1 -Action STOP
# 다음에 다시 시작
.\SECURE-LIFECYCLE.ps1 -Action STARTER
```

STOP은 해당 프로젝트 실행을 종료하며 데이터 볼륨을 삭제하는 절차가 아닙니다. EXE 생성 없이 위 PowerShell 명령을 사용합니다.

## 기존 설치 업데이트

먼저 현재 폴더와 DB/업로드를 백업하세요. 기존 `.env`, `apps/api/.env`, `apps/web/.env.local`, `.starter-state`, `uploads`와 Docker 볼륨을 보존합니다. **기존 설치 경로를 유지**하고 이번 소스 변경 목록을 비교해 적용하세요. 이 ZIP은 사용자 DB의 백업이 아닙니다. 이번 작업은 DB 스키마·마이그레이션 이력을 변경하지 않습니다. 모니터링·환경 검증과 관련 소스 변경은 최신 변경 보고서를 확인하세요.

## 개발자 직접 실행

환경파일과 PostgreSQL/Redis를 준비한 개발자용입니다. 처음 사용하는 Windows 사용자는 위 SETUP을 사용하세요.

```text
npm ci --ignore-scripts
npm run db:generate
npm run db:deploy
npm run dev
```

`db:deploy`는 기존 마이그레이션을 적용합니다. 실행 전 대상 DB와 백업을 확인하세요. DB 초기화나 볼륨 삭제로 오류를 해결하지 마세요.
