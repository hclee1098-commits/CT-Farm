## 보호 대상과 위협

보호 대상은 비밀번호 해시, 인증 세션, MFA 비밀키, 사용자별 게시글/파일, 관리자 권한, DB/업로드/백업, 프로젝트 소유권입니다. 공격자는 비인증 사용자, 다른 일반 회원, 탈취한 Refresh Token/Access Token 사용자, 악성 업로드 제공자, 허용되지 않은 웹 출처, 잘못된 프로젝트 ID를 사용하는 로컬 운영자를 가정합니다. 호스트 관리자 권한 탈취와 Docker 엔진 자체 침해는 이 앱만으로 방어하지 못합니다.

| 경로/위험 | 구현과 검증 | 남은 한계 |
|---|---|---|
| JWT 위조·만료·전체 로그아웃 우회 | HS256/issuer/audience/exp/iat/정수 버전 검사, DB 버전 확인 | V5 JWT 형식 호환을 위해 세션별 Access Token ID 없음 |
| Refresh Token 탈취·재사용 | 원문 미저장, SHA-256, 회원 행 잠금 후 원자적 회전, 재사용 시 전체 버전 증가와 세션 폐기 | 정상 클라이언트의 중복 갱신도 강제 로그아웃할 수 있음. 여러 탭의 갱신 조정 개선 필요 |
| 비밀번호 변경과 로그인 경합 | 로그인 당시 버전을 세션 생성 잠금 안에서 다시 비교 | 네이티브 PostgreSQL 병렬 부하 검증은 별도 |

| MFA 탈취·재사용 | TOTP, 허용 시간 범위 ±1구간, 조건부 갱신으로 OTP 재사용 차단, 복구 코드 해시 1회 소비, AES-GCM 및 사용자 AAD, 10분 등록 기한 | 키 회전 자동화와 분실 시 운영 복구 절차 미구현 |

| 수평 접근 | 노트/파일/세션/알림 DB 조건에 현재 사용자 ID 결합 | 새 서비스 고유 API에도 같은 원칙을 적용해야 함 |
| CSRF·CORS | 웹 쿠키 인증 POST Origin 검증, SameSite Strict·HttpOnly·운영 Secure/__Host 쿠키 | 모바일 토큰은 호출 앱에서 안전하게 보관해야 함 |
| XSS·출력 | React 기본 이스케이프, API/WEB 보안 헤더, 다운로드 접근 통제 | 웹 CSP는 기존 object/base/frame 차단 수준으로 엄격한 script nonce 정책은 미구현 |

## 개인정보·보존

세션에 상세 기기 지문·IP 원문을 추가하지 않습니다. 로그인/민감 작업 이력에는 사용자 ID·행동 코드·시각만 저장합니다. 탈퇴 시 계정 접근을 막고 데이터는 보존하며 비밀번호와 MFA로 30일 내 복구할 수 있습니다. 30일 경과 후 데이터의 자동 파기는 하지 않습니다. 실제 서비스의 보존/파기/다운로드 범위 정책을 확정해야 합니다. 기본 내보내기는 각 범주 최대 1000개이며 파일 내용 대신 메타데이터만 포함합니다.

## 의존성과 공급망

제공받은 잠금 파일을 유지하며 PGlite/PGlite socket 테스트 도구 및 Sharp를 목적에 맞게 추가했습니다. 설치는 lifecycle script를 끈 `npm ci --ignore-scripts`로 재현하고 Prisma 생성은 명시적으로 실행합니다. lockfile의 integrity 정보와 `npm audit` 결과를 첨부합니다. 취약점 데이터베이스의 조회 시점에 한정된 결과이며 알려지지 않은 취약점이 없다는 뜻은 아닙니다.

원본의 `deepmerge-ts:8.0.2` override는 유지했습니다. Prisma 설정 패키지는 7.1.5를 선언하므로 npm의 표준 SBOM 명령이 이를 invalid로 판단했습니다. 그래서 완전한 CycloneDX SBOM을 제공하지 못하며 설치된 패키지의 라이선스 메타데이터 목록을 대체 제공합니다. 실제 빌드·Prisma 생성·migrate deploy·schema diff는 통과 여부를 별도로 기록합니다. override의 업스트림 호환성·라이선스 원문·운영 이미지 취약점은 추가 검토 대상입니다.

## 개발자 플랫폼 보안 검토

- 별도 loopback 서버, 정확한 Host/Origin 검증, 32자 이상 별도 키, 일정 시간 비교, 서버 기준 1시간 만료, 1분 120요청 제한.
- 읽기 GET만 허용. 프로젝트 메타데이터는 키 검증 후 제공. 원문 소스/환경변수 값/파일 읽기/명령/SQL API 없음.
- CSP, no-store, nosniff, no-referrer, textContent 출력. SSE 연결 상한 3개, 2초 배치, 느린 클라이언트 종료.
- 로그는 고정 두 경로에서 필드 allowlist로 읽고 오류 원문과 사용자 제공 메시지를 내보내지 않음. 요청 ID/상태/지연만 보존.
- 기존 관리자 API의 MFA와 일반 사용자 JWT는 유지. 별도 관리자 인증 저장소·VPN·외부 불변 감사 저장소·최소권한 DB 모니터링 계정 구축은 미구현.
- 포털의 감사 이벤트는 stdout만 제공하며 변조 방지 저장소는 아님. 로컬 접근키는 MFA를 제공하지 않음. 운영 관리센터 요구사항 완료로 판단하지 않음.

테스트가 통과한 공격 시나리오와 수행하지 못한 검증은 [결과](../08-이전기록/이전-플랫폼검증.md)를 확인하세요. 이 정적 검토가 모든 CSRF/XSS/SSRF/IDOR 공격의 부재를 보장하지는 않습니다.
