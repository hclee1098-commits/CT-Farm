2026-10-29 (한국 시간). 첨부 V6 부분 구현본의 **문서 구조와 기존 개발자포털을 개선한 전체 소스**입니다. 스타터 플랫폼 전체가 운영 준비를 마쳤다는 판정은 아닙니다.

## 무엇이 달라졌나요?

- 기존 Markdown 24개를 읽고 분류해 `docs/`의 21개로 통합했습니다. 루트에는 짧은 README만 둡니다. 처음에는 설치·기능·구조 3개만 읽으면 됩니다.
- 반복 설치 설명 3개를 합쳤고 소스 폴더 README 5개의 고유 설명은 기술 참고·구조 안내로 합쳤습니다. 이전 결과 4개는 과거 기록으로 분리했습니다.
- 29개 기능 항목에 목적·범위·화면·API·소스·문서·테스트 근거를 연결했습니다. 구현 완료/부분 구현/미구현/확인 필요를 구분했습니다.
- 시스템·API·인증·파일·DB 관계·메일 흐름 등 Mermaid 8개를 제공합니다. 폴더별 수정 위치와 전체 파일 역할 색인을 추가했습니다.
- 기존 포털의 문서 메뉴를 카테고리/문서/세부 목차 화면으로 바꿨습니다. 제목·내용 검색, Markdown 표·코드, Mermaid, 관련 문서 이동과 소스 경로 메타데이터를 제공합니다. 작은 화면은 접이식 목차를 사용합니다.
- 별도 공개 웹사이트나 임의 파일 읽기 API를 만들지 않았습니다. loopback·Host/Origin 검사·32자 접근키·1시간 만료·운영 실행 차단을 유지했습니다.

## 직접 실행하지 못한 검증

- 실제 브라우저 클릭·데스크톱/모바일 배치·Mermaid SVG 시각 검사: Chromium 실행 파일이 없고 다운로드한 응답이 유효한 ZIP이 아니어서 설치에 실패했습니다. DOM 검사와 공식 문법 검사로 대신 확인한 범위를 위에서 구분했습니다. 시각 검사가 성공했다고 처리하지 않았습니다.
- Windows PowerShell 5.1 파서/실행, EXE 컴파일·더블클릭, Docker Desktop·이미지·볼륨 재기동: 해당 실행 환경이 없습니다.
- 네이티브 PostgreSQL·Redis 전체 통합, 실제 pg_dump/pg_restore, 외부 메일 도달: 이번 작업에서 수행하지 않았습니다. PGlite·Mock·격리 SMTP 검사와 다릅니다.

[Windows 실기 확인표](../06-문제해결/Windows-실기검증.md)를 새 테스트 폴더에서 실행하고, 브라우저에서 포털 문서 메뉴·검색·관련 링크·8개 그림·모바일 접이식 목차를 확인하세요.

## 기존 소스와 데이터 보호

원본 209개 파일을 체크섬 기준으로 비교했습니다. 앱의 실행 소스·설정·테스트, Prisma 스키마/마이그레이션, 배포 설정·Compose, 모든 PS1 등 **135개 보호 파일이 바이트 단위로 동일**합니다. 앱 인증·권한·DB 구조는 변경하지 않았습니다. 이전 프로젝트나 운영 DB·CT-Farm·Docker 볼륨에 접근하거나 초기화하지 않았고 Git 커밋도 하지 않았습니다.

변경은 문서, 기존 포털 화면/문서 API 메타데이터, 문서 분석·검사 도구, 로컬 문서 렌더러와 그 의존성에 한정합니다. 문서 표시를 위해 `marked`, `DOMPurify`, `Mermaid`를 개발 의존성으로 추가했습니다. 생성 번들은 실행 전 로컬에서 만들며 외부 CDN을 요청하지 않습니다. API/WEB 운영 Dockerfile은 이 포털을 복사하지 않습니다(정적 확인).

[파일별 비교](../../analysis/docs-preservation.json) · [입력 해시](../../analysis/docs-input-sha256.json) · [문서 이동 목록](문서-이동목록.json)

`backup/문서정리-이전문서.zip`과 `backup/문서정리-이전소스.zip`에 변경 전 문서·관련 소스를 보관했습니다. 전체 원본 첨부는 그대로 보존했습니다. 복원할 때는 별도 빈 폴더에 풀어 비교하고 기존 환경파일·DB·업로드를 덮어쓰지 마세요.

## 결과물 열기와 재검증

1. 전체 ZIP을 새 폴더에 풉니다. `README.md` → `docs/README.md` 순서로 여세요.
2. 웹에서 보려면 [개발자포털 실행](../01-시작하기/개발자포털-실행.md)을 따라 기존 포털을 켜고 **문서센터**를 선택합니다.
3. 개발자 문서 검사는 아래 명령으로 재실행합니다.

```text
npm ci --ignore-scripts
npm run db:generate
npm run predev:portal
npm run test:docs
npm run test:portal
npm run docs:index
npm run docs:check
```

DOM 검사는 별도 준비한 jsdom의 파일 URL을 `DOM_QA_MODULE`로 지정해 `node tools/dev-portal/docs.dom-test.mjs`로 실행합니다. jsdom·브라우저는 프로젝트 실행 의존성으로 추가하지 않았습니다.

ZIP은 실행 소스·설정 예제·잠금 파일·테스트·문서·백업을 포함하며 실제 환경파일, 운영 데이터, node_modules, 빌드 캐시와 테스트 임시 파일은 제외합니다.
