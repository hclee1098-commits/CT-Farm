# 환경 분리와 통합 모니터링 이번 검증 결과

2026-10-29 한국 시간. 원본 `SECURE-STARTER-V6-docs-center.zip`을 실제로 복구·분석·백업한 뒤 같은 프로젝트를 수정했습니다. 별도 신규 앱이나 EXE를 만들지 않았고 Git 커밋·push·원격 배포를 실행하지 않았습니다.

**판정: 소스 구현과 사용 가능한 Linux 격리 검증은 완료했습니다. 실제 Windows·Docker·원격 세 환경의 설치/운영까지 검증 완료한 상태는 아닙니다.** 외부 설정과 실기 검증을 마쳐야 최종 운영 완료 기준을 충족합니다.

## 주요 변경

- STARTER가 실행하는 API의 실제 HTTP 완료 이벤트와 WEB의 Node HTTP 이벤트를 안전한 JSONL로 기록합니다. 이전 표본 래퍼와 포털 사이의 연결 누락을 해소했습니다.
- 독립 collector가 API readiness, WEB 상태 경로, DB/Redis 결과, heartbeat를 수집합니다. 환경별 폴더와 환경 식별자를 검증합니다.
- TLS 중앙 hub의 환경별 쓰기·읽기 키, 권한 분리, 배치/용량/요청 제한, 중복 제거와 재시도를 구현했습니다.
- 운영 모니터링과 실시간 로그를 환경 선택·3환경 비교·서비스/수준/시간/검색 필터·SSE 자동 재연결·중단 감지 화면으로 바꿨습니다.
- 서버용 Docker 구성과 GitHub Actions 예제를 추가했습니다. 동일 digest 명세, STAGING 검증 영수증, 운영 승인 서명, 배포 백업, 실패 시 이전 이미지 복구를 연결했습니다.
- 이메일/백업은 실제 작업 결과를 표시하고 배포/요청에 version을 연결합니다. 기록이 없는 곳에 가짜 상태·배포를 만들지 않습니다.
- 기존 문서센터와 생명주기 관리 구조를 유지했습니다. 세부 변경 파일은 [전체 변경 내역](환경별-모니터링-변경내역.md)을 확인하세요.

## 실패와 수정 기록

- 추가한 API 수집 테스트에서 테스트 대체 DB의 목록 트랜잭션이 빠져 500이 발생했습니다. 실제 HTTP 경계에 적합한 인증된 조회 경로로 테스트를 보완하고 정상·401·500의 관측을 다시 확인했습니다.
- WEB 계측을 처음 파일 접근 코드로 묶었을 때 Next가 전체 프로젝트를 tracing하려는 경고가 있었습니다. 독립 Node preload로 옮겨 다시 빌드했으며 최종 빌드에는 해당 경고가 없습니다.
- 배포 제어 흐름 테스트의 가짜 Docker 실행 파일을 환경에 맞는 셸 fixture로 수정한 후 성공·실패·롤백·암호화 검증을 재실행했습니다. 이것을 실제 Docker 검증으로 집계하지 않았습니다.
- 최종 실행 배치에 남아 있는 실패 항목은 없습니다. 아래 항목은 실행 불가/외부 설정 필요이며 성공으로 처리하지 않았습니다.

## 미검증과 외부 설정 필요

| 대상 | 분류 | 이유 |
|---|---|---|
| Windows PowerShell 5.1 문법/생명주기 실행 | 미검증 | Windows/PowerShell 실행기가 없음 |
| Docker 이미지 빌드/컨테이너/기존 볼륨 재기동 | 미검증 | Docker 엔진/CLI가 없음 |
| 네이티브 PostgreSQL·Redis·Prisma 전체 통합 | 미검증 | 해당 엔진과 기존 사용자 DB에 연결하지 않음 |
| 실제 pg_dump/pg_restore 및 배포 tar 백업·복원 | 미검증 | 실제 Docker/DB 대신 제어 흐름 fixture만 실행 |
| 실제 원격 STAGING/PRODUCTION 로그·헬스·배포·롤백 | 외부 설정 필요 | 호스트·도메인·인증서·서버 키 없음 |
| 실제 GitHub Actions 실행·승인 보호 | 외부 설정 필요 | 저장소·runner·GHCR 권한·Required reviewers 설정 없음 |
| 외부 SMTP 도달 | 외부 설정 필요 | 실제 발송 계정 없음 |
| 실제 브라우저 시각 검사 | 미검증 | Chromium 실행 파일 없음. jsdom 동작 검사만 실행 |

## 데이터 보호 근거

- 변경 전 원본 전체 소스를 `backup/환경분리-수정전소스.zip`으로 보관했습니다. 사용자 DB·업로드 백업이 아니라 제공받은 소스 백업입니다.
- 원본과 바이트 비교하여 기존 LOCAL compose.yaml, Prisma 스키마, 모든 migration, package-lock.json이 동일함을 확인했습니다.
- 실제 사용자 `.env`, DB, Redis, Docker 볼륨, 관리자/사용자 데이터에 접근하거나 변경하지 않았습니다. 배포 ZIP에 실제 환경설정·키·DB·수집 로그를 포함하지 않습니다.
- 기존 CRUD/인증/파일 소스와 회귀 테스트를 유지했습니다. 새 API 계측과 환경 검증은 실제 소스에 반영했습니다.
- Git 명령으로 커밋하거나 push하지 않았고 운영 서버를 변경하지 않았습니다.
