## 수정 내용

| 문제 | 수정 및 영향 |
|---|---|
| 로그인에서 bcrypt의 72바이트 제한을 초과해도 입력 허용 | 로그인도 UTF-8 72바이트로 제한. 앞 72바이트가 같은 다른 입력이 동일 비밀번호로 취급되는 문제 방지. 72바이트 이하 기존 비밀번호 유지 |
| 미가입 이메일은 bcrypt 비교 없이 즉시 실패 | 같은 비용의 더미 해시와 비교 후 동일한 인증 오류 반환. 큰 처리 시간 차이 완화 |
| JWT 사용자 버전의 정수 조건과 필수 시간 클레임 검사 부족 | 음수·소수 버전 및 exp/iat 없는 토큰 차단. 기존 발급 토큰은 그대로 허용 |
| 잘못된 연결 URL·빈 업로드 경로·예시 JWT 키 허용 | 독립 환경 스키마와 회귀 테스트 추가. 올바른 PostgreSQL/Redis URL, HTTP(S) 출처, 운영 HTTPS 조건 검증 |
| 인증·개인 API 응답의 공통 캐시 방지 누락 | API 응답에 private/no-store 및 Pragma 추가 |
| 공통 API 클라이언트가 URL 정규화 후 API 경계를 재검사하지 않음 | 정규화 후 출처·API 경계 재검사, 제어문자 차단, 경로 오류 코드 유지 |
| 인증을 포함한 fetch가 리다이렉트를 자동 추적 | 공통·보조·인증 클라이언트에서 리다이렉트 오류 처리 |
| 웹 클라이언트별 API 환경 변수 우선순위 불일치 | 공통 config.ts로 통합. 누락된 웹 환경 예시 추가 |
| 인증 POST가 응답을 무한 대기할 수 있음 | 로그인·회원가입·갱신·현재 기기 로그아웃 POST에 15초 제한. JSON 본문 처리 완료까지 적용 |
| 늦은 로그인 응답이 로그아웃 이후 메모리 토큰을 복구할 수 있음 | 로그인·회원가입에도 인증 세대 검사 적용. 브라우저 쿠키 응답 순서의 모든 경쟁 상황을 해결했다는 의미는 아님 |
| 전역 오류 로그에 외부 오류 원문 포함 | 전역 처리기에서 오류 유형·공통 코드만 기록하여 SQL/연결 비밀값 노출 방지 |
| 공통 오류 처리기가 두 개이며 동작이 다름 | AppError 타입을 분리하고 기존 errors.ts 경로는 실제 전역 처리기로 연결 |
| Redis의 기본 무한 재접속/오프라인 큐 누적 가능 | 연결 시간·재접속 횟수·큐 길이 제한, 오프라인 큐 비활성화. 서버 시작에서도 같은 연결 Promise 사용 |
| 업로드 서비스가 Multer의 크기 검사에만 의존 | 버퍼 실측 크기·메타데이터 일치 여부·5MiB 제한 검사 추가 |
| 웹 의존성이 latest로 선언됨 | 잠금 파일의 실제 검증 버전으로 Next/React/React DOM 고정 |
| package main 및 이전 dev 명령이 없는 서버 파일을 가리킴 | 실제 bootstrap 진입점으로 수정 |
| 웹 루트 페이지 없음 | / 접근 시 /starter로 이동 |
| V5 통합 테스트의 고정 포트/정리 프로젝트 지정 누락 | 설치 식별자·경로·포트 검사. Docker 정리 시 프로젝트와 compose 파일을 명시하고 env 프로젝트가 일치하는지 확인 |
| 제공된 런처 C# 소스가 SETUP 이름을 거부 | SETUP/STARTER/STOP 모두 허용. 기존 EXE 백업 후 생성하는 Windows 컴파일 스크립트 추가 |
| 이전 부별 생성 스크립트의 보안 수정 되돌림 가능 | 보안 수정 표식이 있는 대상에 적용을 차단. 원본의 빈 복구 스크립트는 명시적 오류로 중단 |
| PowerShell 인코딩 유지 장치 부족 | 모든 PS1을 단일 UTF-8 BOM/CRLF로 저장. editorconfig와 BOM/문법 검사 스크립트 추가 |

원래 기능의 회원가입·로그인·Refresh 회전·전체 로그아웃, 게시글 소유권 검사, 파일 비공개 저장·다운로드·삭제 복구는 유지했습니다. 파일 접근과 삭제 보호를 실제 디스크 테스트로 추가 확인했습니다. Prisma 스키마와 마이그레이션 SQL, Docker 볼륨 설정은 변경하지 않았습니다.

## 원본·데이터 보호

- 소스 수정 전에 `original-backup.zip`을 생성했습니다. 첨부된 3개 원본 텍스트를 그대로 포함하고, 당시 복원한 프로젝트도 함께 보관했습니다. 첨부 원본의 SHA-256은 별도 목록에 있습니다.
- 텍스트에서 복원한 프로젝트는 줄바꿈/인코딩 변환을 포함하므로 첨부 전 개별 파일의 원래 바이트를 재현한 백업으로 간주하면 안 됩니다. 첨부 텍스트 자체는 원본 그대로 보존했습니다.
- 실제 사용자 DB, 업로드 파일, 환경 파일, 설치 상태, 기존 EXE는 첨부에 없었습니다. 이 자료의 데이터 백업을 만들거나 실제 DB를 테스트했다고 주장하지 않습니다. 운영 데이터에는 접근하지 않았습니다.
- `node_modules`, 빌드 산출물, 테스트 임시 파일은 배포본에서 제외했습니다. 소스·패키지 잠금 파일·테스트·설정·실행 도구는 포함했습니다. 새 환경에서 npm ci로 설치하세요.
- API의 vitest.config.ts는 ESM 설정 경고를 없애기 위해 vitest.config.mts로 이동했습니다. 설정 내용은 유지했습니다.

## 클라우드에서 검증하지 못한 항목

1. Windows PowerShell 5.1 파서와 실제 실행: BOM은 바이트 수준에서 확인했지만 이 환경에는 powershell/pwsh가 없습니다. 새 PS1 코드는 5.1 문법과 .NET Framework API 범위로 작성했습니다. 최종 호환성은 Windows에서 `tools/verify-powershell.ps1`로 확인해야 합니다.
2. Windows EXE: 기존 SETUP/STARTER/STOP 바이너리가 제공되지 않았고 C# 컴파일러도 없습니다. 수정한 C# 소스와 생성 스크립트만 포함했습니다. EXE 컴파일, 더블클릭, 숨김 창, 실제 프로세스 소유권·종료, 포트 선택은 Windows에서 검증해야 합니다.
3. Docker Desktop/Compose: 엔진과 CLI가 없어 컨테이너 생성, 소유권 검사, 볼륨 재사용, 기존 DB 보호, 설치 중단 후 복구, 통합 테스트 정리 동작을 실제로 실행하지 못했습니다.
4. 실제 PostgreSQL/Redis 통합: DB 마이그레이션 적용, 트랜잭션/잠금의 실서버 동작, Redis 공유 요청 제한과 재연결은 실서비스 환경 검증이 필요합니다. HTTP 테스트에서는 외부 의존성을 대체했습니다.
5. 실제 브라우저: Next 화면의 HTTP 응답은 확인했지만 브라우저 클릭, 탭 간 인증/쿠키 순서 경쟁, Windows 파일 다운로드 대화상자는 검사하지 않았습니다.

이 항목은 통과로 처리하지 않았습니다. Windows 검증 순서는 README-START-HERE.md에 있습니다.

## 포함된 증거

- `verification/verify-final.log`: 신규 설치 후 전체 검증 출력
- `verification/install-final.log`: npm ci 출력
- `verification/web-smoke-final.log`: 빌드된 실제 Next 서버 검사 출력
- `verification/changes.patch`: 텍스트 코드 변경 내역(BOM/줄바꿈만의 변경은 생략)
- `verification/change-index.txt`: 변경/추가/이동 경로
- `verification/SOURCE-SHA256.txt`: 전달 소스 체크섬
- `verification/ATTACHMENTS-SHA256.txt`: 첨부 원본 체크섬
- `backup/original-backup.zip`: 수정 전 첨부 원본과 복원 소스
