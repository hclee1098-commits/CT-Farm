# SECURE STARTER V6 구현·검증 보고서

작성일: 2026-10-28 · 버전: **6.0.0-rc.1**

## 판정

**소스 수정과 실행 검증을 수행한 V6 검증 후보판입니다. 요청한 전체 완료 기준을 충족한 정식 운영판으로 판정하지 않습니다.** Docker/Windows/네이티브 PostgreSQL 백업·복원 검증과 아래 미구현 기능이 남아 있습니다. 외부 환경 제약과 구현 미완료를 구분했습니다.

CT-Farm, 기존 사용자 DB/파일, 외부 프로젝트의 컨테이너·볼륨에 접근하거나 변경하지 않았습니다. Git 커밋·푸시·브랜치 변경도 하지 않았습니다. 테스트에서 생성한 임시 DB와 파일만 사용했습니다.

## 입력과 복원

최신 `SECURE-STARTER-WORK-전체소스_01(1).txt`의 프로젝트 내부 125개 소스 섹션을 `secure-starter-v6/`로 복원했습니다. 프로젝트 외부 검증 자료는 실행 소스로 취급하지 않았습니다. 원본 첨부가 명시적으로 제외한 API/WEB `vitest.config.mts` 2개는 다시 작성했습니다. 원본 EXE, 원본 ZIP 바이너리, 실제 환경파일과 DB는 제공되지 않았으므로 복원했다고 주장하지 않습니다.

중요 파일을 바꾸기 전 복사한 V5 소스는 `backup/V5-source-before-changes.zip`으로 포함합니다. 이는 제공받은 소스의 백업이며 운영 데이터 백업이 아닙니다. `verification/v5-source-sha256.json`과 `verification/change-list.json`에 비교 기준과 변경 내역을 기록합니다.

## 발견한 문제와 수정

- V5 회전 토큰 재사용 시 단순 거부만 하던 경로를 전체 세션 폐기로 보강했습니다. 회전 경합에서 재사용으로 판정된 경우에도 트랜잭션 밖에서 폐기를 커밋합니다.
- 비밀번호 검증 후 계정 상태가 바뀌어도 새 세션을 만들 수 있는 경합에 로그인 시점 버전 비교를 추가했습니다.
- 로그에 외부 오류 원문이 들어갈 수 있어 민감정보를 포함할 수 있는 오류 상세를 제거했습니다.
- V6 SQL 작성 중 Prisma와 외래키 ON UPDATE 동작이 다른 것을 migrate diff로 발견해 맞췄습니다. 현재 통합 테스트가 적용 결과와 스키마 차이 없음을 확인합니다.
- 파일 해시 추가 시 삭제 저널에 잘못 적용된 코드를 API 빌드 오류로 발견해 수정했습니다.
- UI 확장 중 기존 export를 덮어써 호환성이 깨진 것을 WEB 빌드로 발견했습니다. 기존 UI를 복구하고 없는 컴포넌트만 추가했으며 이후 빌드/회귀 테스트를 통과했습니다.
- 삭제 조건 변경으로 이전 HTTP 테스트의 기대 조건이 달라진 부분에 deletedAt 조건을 포함했습니다.
- 신규 업로드 실패 테스트의 파일 크기 fixture 불일치를 수정했고, 실제 디스크/DB 실패 경로까지 도달하는지 검증하도록 강화했습니다.
- 중간 WEB 빌드에서 생성 캐시의 ENOTEMPTY를 만나 `.next` 생성물만 정리한 뒤 재빌드했습니다. DB나 사용자 파일은 초기화하지 않았습니다.

## DB 마이그레이션

기존 `20261026153448_init`은 변경하지 않았습니다. 추가한 `20261028180000_v6_security`는 다음을 포함합니다.

- User: 역할, 정지/탈퇴/이메일 인증, MFA 암호문/사용 여부/등록 기한/마지막 OTP 구간/복구 코드 해시, 로그인 실패 잠금, 이메일 알림 선호.
- Note: deletedAt, version.
- StoredFile: deletedAt, nullable sha256, 소유자·해시 인덱스. 기존 파일의 원본 바이트나 해시를 임의로 바꾸지 않습니다.
- AuditEvent, AccountAction, Notification, IdempotentRequest 테이블과 인덱스/참조 제약.

기존 테이블/행 삭제·DB reset·볼륨 삭제는 포함하지 않습니다. 실제 기존 대용량 DB의 ALTER 소요시간과 잠금은 미측정입니다. 업그레이드 전에 백업과 서비스 정지가 필요합니다. 다운 마이그레이션은 제공하지 않으며 앱 롤백 시 추가 열을 유지합니다.

## 구현 미완료와 제한

다음은 환경이 아니라 **구현이 남은 항목**입니다.

- 백업 자동 스케줄 등록, 자동 보관 정책, 실패 알림, 관리자 백업 작업/복원 UI. 현재 수동 CLI와 절차만 제공합니다.
- 완전한 운영 복원 검증과 자동 복구. DB 복원 성공 후 파일 단계 실패 시 둘을 하나의 트랜잭션으로 롤백하지 못합니다.
- 범용 RBAC 정책 편집, 회원 상세 페이지, 최근 오류 로그 검색, 시스템 설정/큐/백업 실측 대시보드. 현재 역할은 USER/ADMIN 두 가지입니다.
- 계정 프로필·이메일 변경·복구·데이터 내보내기 UI. API는 제공하지만 계정 화면은 MFA/비밀번호/세션 위주입니다.
- 완전한 OpenAPI 요청/응답 스키마 및 자동 생성 계약 테스트. 현재 경로/주요 DTO 문서와 실제 HTTP 테스트입니다.
- 상세한 모든 보안 실패 감사 이벤트, 외부 로그 보관/경보, MFA 암호화키 회전/분실 복구 자동화.
- 저장소 할당량, 자동 영구 삭제/보존 정책, 대용량 스트리밍 백업, PDF 악성코드 검사, 모든 동시 중복 파일의 유일성 보장.
- 일반형 이메일 템플릿·발송 이력·재시도 큐. 메모리 Mock은 최대 100건만 보관하고 외부 발송을 하지 않습니다.
- 선택적 큐/실시간 통신/웹훅/결제/SMS/지도/OAuth/S3 구현체.
- 전체 공통 UI의 다크 모드/접근성/반응형 브라우저 E2E. 기존 공통 UI와 일부 추가 컴포넌트만 정적 검증했습니다.
- 라이선스 원문/법률 검토 및 완전한 표준 SBOM. 기존 deepmerge-ts override로 npm sbom이 invalid 판정을 내리며 메타데이터 목록을 대체 제공합니다.

따라서 **요청한 최종 완료 기준 중 모든 필수 공통 기능·운영 백업/복원·Windows 신규 설치/실행/종료·Docker 동시 격리 검증은 아직 충족하지 않았습니다.** 현재 결과를 바로 운영 서비스에 투입하는 대신, 미검증 확인표와 남은 기능을 기준으로 추가 검증해야 합니다.
