# 실제 코드로 보는 시스템 구조와 기능 흐름

기준일: 2026-10-30. 구현 파일의 존재와 운영 검증을 구분합니다. 최신 웹·별도 앱 범위는 [모바일 앱과 디자인](모바일앱과-디자인.md), 음성·협업·장애 검증은 [6차 결과](6차-음성과-실행복구.md)를 함께 읽으세요.

## 전체 아키텍처와 프론트·백엔드 연결

```mermaid
flowchart LR
 U[농민 브라우저] --> W[Next.js starter 화면]
 W --> A[Express API v1]
 A --> P[Prisma]
 P --> DB[(PostgreSQL)]
 A --> R[(Redis 요청 제한)]
 A --> F[로컬 파일 저장소]
 A -. 선택 설정 .-> E[지도 · 날씨 · AI · 테스트 PG]
```

## API 요청·응답

```mermaid
sequenceDiagram
 participant W as 화면
 participant A as Express
 participant S as 서비스
 participant D as PostgreSQL
 W->>A: 인증된 요청
 A->>A: requireAuth 및 Zod 검사
 A->>S: 사용자 범위 작업
 S->>D: 소유권 및 transaction 검사
 D-->>S: 결과 또는 충돌
 S-->>A: 성공 또는 AppError
 A-->>W: JSON 및 HTTP 상태
```

## 알림 생성·전달

```mermaid
flowchart LR
 C[사용자 점검 또는 설정된 worker] --> B[buildAdvice]
 B --> D[작기 · 일정 · 센서 · 날씨 규칙]
```

## AI 상담·분석

```mermaid
flowchart TD
 Q[상담 요청] --> A[소유권 · 멱등성 · 안전 검사]
 A --> M{모드}
 M -->|REFERENCE| R[공식 포털 탐색 안내]
 M -->|MODEL| C[동의 · 서버 설정 · 예산 예약]
 C --> P[최소 농장 문맥 · 허용 자료 ID]
 P --> O[외부 모델 어댑터]
 O --> V[출력 스키마 · 근거 · 안전 검사]
 V --> H[상태 · sources · usage 이력]
 R --> H
```

농장 추천은 별도 규칙 엔진입니다. 생성형 모델이 물리 장치를 제어하지 않습니다.
